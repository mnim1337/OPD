# OPD

При повторном импорте одинакового четырёхфайлового комплекта приложение предлагает открыть сохранённую версию с её Ω или создать связанную копию; порядок описан в [руководстве по вводу](docs/user-guide/data-entry.md).

Проект настольной программы для комплексной оценки алгоритмов маршрутизации в многоспутниковых системах связи.

- [Исходное ТЗ](requirements/ТЗ_Оценка_маршрутизации_единый_документ.docx) — ТЗ-ОАМ-01, версия 1.0; пользователь подтвердил её как текущую итоговую редакцию 23 октября 2026 г.
- [План работ по главам ТЗ](requirements/tasks.md) — задачи, зависимости и критерии готовности.
- [План разработки](docs/development/development-plan.md) — последовательность поставок, контрольные точки и открытые решения.
- [Матрица требований](requirements/traceability.md) и [сценарии приёмки](docs/development/acceptance-scenarios.md) — состав проверок по ТЗ.
- [Визуальная приёмка на Windows](docs/development/windows-visual-acceptance.md) — маршрут и протокол сверки экранов этапа 4 с приложением В.
- [Открытые решения](requirements/open-questions.md) и [рабочие численные допуски](docs/development/numerical-test-plan.md) — вопросы до приёмки.
- [Исходные контрольные материалы](requirements/source-materials.md) — состав и назначение архивов.
- [Понимание предметной области](understanding.md) — подтверждённые сведения и открытые вопросы.

Текущая версия `0.6.1` реализует ввод, расчёт К0–К3, сохранение и просмотр результатов, сравнение и серии, экспорт JSON/CSV/PNG, резервное копирование и восстановление. П05 содержит девять форм паспорта; страницы узлов, соединений, потоков и событий показывают отдельные карточки списка и выбранной записи, «Проверки» — две соседние таблицы, «Полнота» — качество регистрации и сведения о формате по рисункам В.12–В.24 ТЗ. Дополнительные поля остаются редактируемыми без потери исходного JSON. Журналы пакетов, маршрутов и каналов позволяют копировать всю выбранную запись. Расчётный алгоритм описан в [документации К0–К2](docs/algorithms/k0-k2.md) и [К3](docs/algorithms/k3.md). Визуальная приёмка всех состояний на Windows, испытание крупной реальной выгрузки и согласование PDF-шаблона ещё требуются. [Установка и проверки](docs/development/setup.md) · [Руководство по вводу](docs/user-guide/data-entry.md) · [Расчёт и результаты](docs/user-guide/calculation.md). Язык — Python, GUI — PySide6/Qt Widgets.

Проверочную Windows-сборку этапа 6 можно получить из успешного запуска workflow **Windows test build** в GitHub Actions ветки `feat/stage-6-delivery`; порядок скачивания и проверки описан в [инструкции этапа 6](docs/development/windows-stage6-testing.md). Пользователь подтвердил запуск прежней сборки `.exe` на Windows; визуальная проверка версии `0.6.1` и статус нового удалённого workflow пока не подтверждены.

Для расчёта нужен профиль Ω: загрузите согласованный JSON через «Загрузить Ω». Для синтетических контрольных опытов приложен [демонстрационный профиль](configs/examples/profile_demo.json); его шкалы не утверждены для реальных данных.

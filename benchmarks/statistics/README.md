# Журнал запусков

`runs.jsonl` создаётся при первом экспериментальном запуске и пополняется только добавлением строк. Каждый непустой ряд — один JSON-объект для одного запуска, включая неудачные и прерванные. Историю не переписывать. Полные результаты, конфигурацию и логи держать в `outputs/runs/<run-id>/`; этот каталог исключён из Git.

Обязательные поля записи:

| Поле | Содержание |
| --- | --- |
| `run_id`, `started_utc`, `finished_utc` | Уникальный ID и фактическое время запуска. |
| `purpose`, `method`, `command`, `parameters` | Гипотеза/цель, методика, точная команда и параметры. |
| `code_commit`, `tree_state`, `diff_artifact` | Commit, состояние рабочего дерева и путь к сохранённому diff при незакоммиченных изменениях. |
| `dataset`, `reference` | ID, версия, контрольная сумма и происхождение входа и эталона; `null` с причиной, если эталона нет. |
| `environment`, `dependencies`, `seed` | ОС, архитектура, Python, зависимости, ресурсы и seed случайных процедур; `null` с причиной, если не применяется. |
| `accuracy` | Измеренная ошибка с единицей, агрегированием, эталоном и допуском. При отсутствии измерения — `null` и отдельная причина. Ноль не означает отсутствие данных. |
| `effectiveness` | Статус запуска, достижение заранее заданного критерия и число успешных случаев из общего числа. Если критерий ещё не согласован — `null` с причиной. |
| `artifacts`, `external_artifact_uri` | Пути полных локальных артефактов и постоянная внешняя ссылка для значимых запусков, если есть. |

Причины неизвестных значений записывать рядом, например `accuracy_reason` и `effectiveness_reason`. Для времени обработки указывать измеренную фазу и единицу; для памяти — способ измерения и единицу. Статистика производительности не является точностью расчётов. В записи не хранить секреты, абсолютные пути к личным данным и содержимое реальной выгрузки.

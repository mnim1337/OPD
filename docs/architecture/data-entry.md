# Импорт, черновики и экспорт

**Реализация этапа 2:** `src/scanner/io/model.py`, `format.py`, `validation.py`, `profile.py`, `storage.py`; `src/scanner/gui.py`, `cli.py`. Источники: ТЗ-ОАМ-01 версии 1.0, § 4, § 8–9, приложение А; [проект контракта](input-and-run-contract.md).

```text
четыре файла → синтаксический разбор → общая модель ← ручной редактор
                                      ↓
                              общая валидация
                             ↙              ↘
                  SQLite черновиков      экспорт 4 файлов
```

`Experiment` содержит паспорт, три таблицы и при импорте оригинальные байты всех четырёх файлов. После нормализации CSV-числа представлены `Decimal`, целые значения — `int`, `link_up` — `bool`, `path_links` — списком строк, пустое необязательное поле — `None`. Паспорт хранится как вложенный JSON-объект и проходит структурную и семантическую проверку; имена и точные типы полей задаёт приложение А. И импорт, и ручной ввод проходят `normalize_rows` и `validate_experiment` перед проверкой/экспортом. Экспорт создаёт новые байты с CRLF для CSV и LF для JSON, формирует `row_count`, `size_bytes`, SHA-256 трёх CSV и записывает паспорт последним.

SQLite создаёт неизменяемые строки `drafts(draft_id, revision, created_utc, source, passport_json, tables_json, profile_json)`. Здесь таблицы черновика хранятся как введённые строки, включая пустые и ошибочные ячейки: такую работу можно сохранить и затем исправить. `originals` хранит байты исходного импорта по версии черновика. `profiles` хранит профиль по `(profile_id, version)` и SHA-256 содержания, `draft_profiles` связывает версию черновика с версией Ω. Сохранение использует транзакцию `BEGIN IMMEDIATE`; сбой до commit не меняет прежние версии. Экспорт полного комплекта требует успешной типизации и проверки. Это хранилище пока не содержит результатов расчёта или серий, которые появятся на следующих этапах.

Диагностика имеет поля `severity`, `code`, `location`, `field`, `message`, `remedy`. Синтаксические ошибки импорта останавливают чтение с адресным сообщением; общая семантическая проверка собирает несколько ошибок и предупреждений. Допустимая неполнота наблюдений не превращается в ноль. Чтение файлов не исполняет выражений из данных.

Ограничения ввода: модель паспорта проверяется во время выполнения, но не описана отдельными Python-классами для каждого вложенного блока; специфические подформы П05 ещё не реализованы. Экспертные оценки Ω обрабатывает отдельное [расчётное ядро](calculation-core.md), но GUI пока не предоставляет для них подформу. Фактическая производительность на больших выгрузках и целевой Windows не измерена.

# Запуск расчёта и хранение результата

Этап 4 связывает Qt-редактор с ядром К0–К2 и SQLite. Формулы остаются только в `scanner.core`; GUI передаёт состояние редактора диспетчеру, затем показывает результат.

Визуальная оболочка `src/scanner/gui.py` использует общую палитру и стили Qt Widgets для навигационных П01–П04, редактора П05, результата П06, истории П07 и справочных С01–С02. Основные страницы остаются в `MainWindow.pages` (`QStackedWidget`); оформление не меняет контракт диспетчера расчёта или структуру сохранённого результата. Страницы С01–С02 заменили модальные информационные окна. На П05 служебные действия находятся в меню шапки, а заголовок связан с выбранной формой паспорта. П07 загружает сохранённый результат и его входной паспорт для строки таблицы: показывает алгоритм, сценарий, повтор, модель, состояние и итог; поиск и два списка фильтров скрывают несоответствующие строки и снимают выбор при отсутствии совпадений. Открытие использует ID выбранной записи, расчёт повторно не вызывается. Полная визуальная проверка всех форм П05 и вспомогательных состояний по приложению В на Windows остаётся задачей этапа 4.

## Запуск

`scanner.core.dispatcher.calculate_and_save` сначала выполняет общую проверку данных и профиля Ω. При блокирующих ошибках снимок не создаётся, расчёт не запускается. Для корректного набора диспетчер сохраняет новую неизменяемую ревизию входа вместе с профилем, считывает эту ревизию обратно и рассчитывает именно её. Изменения формы после фиксации не меняют запущенный набор. GUI выполняет запуск в `QThread`, показывает текущую фазу и принимает запрос отмены. Ядро проверяет отмену на границах подготовки К0, показателей К1 и оценивания К2; одна выполняющаяся фаза завершается прежде, чем запрос будет обработан. При отмене частичная оценка не сохраняется, зафиксированный снимок входа остаётся в истории.

Успешный результат добавляется в `assessments` и содержит внешний ключ на ревизию входа, точную версию профиля и версию модели. Сам результат сериализуется целиком, включая исходные и нормализованные показатели, статусы границ, трассы, предупреждения и профиль. История загружает сохранённый JSON и не вызывает расчёт.

Если расчёт завершился, а запись результата не удалась, диспетчер возвращает рассчитанный объект через `ResultPersistenceError`. GUI явно сообщает, что результат не сохранён, показывает его и оставляет действие повтора записи. Повтор использует готовый JSON и не запускает ядро снова. Пока ошибка не устранена, такой результат существует только в памяти процесса.

## Результат и экспорт

Панель результата содержит контекст и состояние сохранения, таблицу семи показателей рядом с радаром частных баллов, групповые значения, полосы вкладов на вкладке сравнения, диаграмму Ганта с выбором потоков/каналов и увеличением участка события, а также трассу и предупреждения. Заголовок и код П06.1–П06.4 меняются с вкладкой; карточка I(A) относится к первой вкладке. Таблица по умолчанию показывает шесть основных колонок; статус, направление, нормализация и пояснение остаются в том же виджете и раскрываются кнопкой. Для интервального и неприменимого итога показана отдельная причина без подстановки нуля или перераспределения веса. Вкладка сравнения читает две выбранные сохранённые оценки из серии, проверяет сопоставимость их входов и профилей, показывает две строки и две накопительные полосы семи вкладов. Неизвестные и интервальные вклады не превращаются в ноль или середину интервала; при различии условий причины видны, общий рейтинг не формируется. Диаграмма Ганта берёт интервалы только из сохранённых строк маршрутов и каналов. Обзор сначала показывает два потока, затронутый канал и канал другого наблюдавшегося пути, если такие строки есть; через выбор доступны все строки. Первому установленному пути и другому наблюдавшемуся пути назначены разные цвета, без утверждения о роли «резерва» при отсутствии этого признака в данных. Пустые промежутки и зарегистрированное неизвестное состояние получают разные штриховки. Вкладка пояснений показывает для адаптивности фактический момент события, измеренную длительность, начало нового пути и отдельное подтверждение; полный JSON трассы открывается отдельно. Точечные, интервальные и неизвестные значения показываются русскими подписями при сохранении исходных статусов в данных. JSON сохраняет полный результат и Ω; CSV содержит табличные значения семи показателей, включая границы и статусы; графики экспортируются в PNG. Сохранённые оценки можно объединять в именованные серии и закрывать их без удаления или пересчёта. Прямое сравнение двух оценок вне вкладки серии также показывает предупреждения о различии сети, заданной нагрузки, расписания внешних вмешательств, измерительной конфигурации, шкал и весов; фактическое время и результат вмешательства рассматриваются как наблюдённый исход и не формируют общий рейтинг при различии условий.

Ядро анализа чувствительности и описательной статистики повторов этапа 5 доступно через CLI; подключение К3 к GUI и хранилищу впереди. PDF остаётся заблокирован открытым вопросом Q-05 до согласования шаблона. Текущие автоматические проверки подтверждают обработку синтетических комплектов; ручная приёмка полного UI-цикла и интеграция с реальной выгрузкой ПАК не выполнены.

## Хранилище

Схема дополняется таблицами `assessments`, `series` и `series_assessments`; прежние таблицы черновиков и профилей сохраняются. Каждая оценка добавляется отдельной записью. `DraftStore.backup` использует встроенное резервное копирование SQLite, чтобы копия была согласованной при открытом приложении. Восстановление проверяет целостность, связи и наличие таблиц OPD, копирует файл во временное хранилище рядом с рабочим и атомарно заменяет его. Для старых копий таблицы серий создаются миграционно.

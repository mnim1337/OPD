# Запуск расчёта и хранение результата

Этап 4 связывает Qt-редактор с ядром К0–К2 и SQLite. Формулы остаются только в `scanner.core`; GUI передаёт состояние редактора диспетчеру, затем показывает результат.

Визуальная оболочка `src/scanner/gui.py` использует общую палитру и стили Qt Widgets для навигационных П01–П04, редактора П05, результата П06, истории П07 и справочных С01–С02. Основные страницы остаются в `MainWindow.pages` (`QStackedWidget`); оформление не меняет контракт диспетчера расчёта или структуру сохранённого результата. Страницы С01–С02 заменили модальные информационные окна. П07 показывает таблицу сохранённых оценок; поиск скрывает несоответствующие строки и снимает выбор при отсутствии совпадений, открытие использует ID выбранной записи. Полная визуальная проверка форм П05, деталей П07 и вспомогательных состояний по приложению В остаётся задачей этапа 4.

## Запуск

`scanner.core.dispatcher.calculate_and_save` сначала выполняет общую проверку данных и профиля Ω. При блокирующих ошибках снимок не создаётся, расчёт не запускается. Для корректного набора диспетчер сохраняет новую неизменяемую ревизию входа вместе с профилем, считывает эту ревизию обратно и рассчитывает именно её. Изменения формы после фиксации не меняют запущенный набор. GUI выполняет запуск в `QThread`, показывает текущую фазу и принимает запрос отмены. Ядро проверяет отмену на границах подготовки К0, показателей К1 и оценивания К2; одна выполняющаяся фаза завершается прежде, чем запрос будет обработан. При отмене частичная оценка не сохраняется, зафиксированный снимок входа остаётся в истории.

Успешный результат добавляется в `assessments` и содержит внешний ключ на ревизию входа, точную версию профиля и версию модели. Сам результат сериализуется целиком, включая исходные и нормализованные показатели, статусы границ, трассы, предупреждения и профиль. История загружает сохранённый JSON и не вызывает расчёт.

Если расчёт завершился, а запись результата не удалась, диспетчер возвращает рассчитанный объект через `ResultPersistenceError`. GUI явно сообщает, что результат не сохранён, показывает его и оставляет действие повтора записи. Повтор использует готовый JSON и не запускает ядро снова. Пока ошибка не устранена, такой результат существует только в памяти процесса.

## Результат и экспорт

Панель результата содержит контекст и состояние сохранения, таблицу семи показателей, групповые значения, радар частных баллов, полосы вкладов, диаграмму Ганта с выбором потоков/каналов и увеличением участка события, а также трассу и предупреждения. JSON сохраняет полный результат и Ω; CSV содержит табличные значения семи показателей, включая границы и статусы; графики экспортируются в PNG. Сохранённые оценки можно объединять в именованные серии и закрывать их без удаления или пересчёта. Сравнение двух сохранённых оценок содержит таблицу семи показателей и две накопительные полосы из семи взвешенных вкладов с итогом I(A); интервалы штрихуются как диапазон без подстановки середины. Прямое сравнение показывает предупреждения о различии сети, заданной нагрузки, расписания внешних вмешательств, измерительной конфигурации, шкал и весов; фактическое время и результат вмешательства рассматриваются как наблюдённый исход и не формирует общий рейтинг при различиях условий. Неизвестные и интервальные состояния не преобразуются в числовой ноль или середину интервала.

Сравнение настоящих статистических повторов и анализ чувствительности относятся к этапу 5. PDF остаётся заблокирован открытым вопросом Q-05 до согласования шаблона. Текущие автоматические проверки подтверждают обработку синтетических комплектов; ручная приёмка полного UI-цикла и интеграция с реальной выгрузкой ПАК не выполнены.

## Хранилище

Схема дополняется таблицами `assessments`, `series` и `series_assessments`; прежние таблицы черновиков и профилей сохраняются. Каждая оценка добавляется отдельной записью. `DraftStore.backup` использует встроенное резервное копирование SQLite, чтобы копия была согласованной при открытом приложении. Восстановление проверяет целостность, связи и наличие таблиц OPD, копирует файл во временное хранилище рядом с рабочим и атомарно заменяет его. Для старых копий таблицы серий создаются миграционно.

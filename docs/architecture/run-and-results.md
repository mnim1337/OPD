# Запуск расчёта и хранение результата

Первая часть этапа 4 связывает Qt-редактор с ядром К0–К2 и SQLite. Формулы остаются только в `scanner.core`; GUI передаёт состояние редактора диспетчеру, затем показывает результат.

## Запуск

`scanner.core.dispatcher.calculate_and_save` сначала выполняет общую проверку данных и профиля Ω. При блокирующих ошибках снимок не создаётся, расчёт не запускается. Для корректного набора диспетчер сохраняет новую неизменяемую ревизию входа вместе с профилем, считывает эту ревизию обратно и рассчитывает именно её. Изменения формы после фиксации не меняют запущенный набор.

Успешный результат добавляется в `assessments` и содержит внешний ключ на ревизию входа, точную версию профиля и версию модели. Сам результат сериализуется целиком, включая исходные и нормализованные показатели, статусы границ, трассы, предупреждения и профиль. История загружает сохранённый JSON и не вызывает расчёт.

Если расчёт завершился, а запись результата не удалась, диспетчер возвращает рассчитанный объект через `ResultPersistenceError`. GUI явно сообщает, что результат не сохранён, показывает его и оставляет действие повтора записи. Повтор использует готовый JSON и не запускает ядро снова. Пока ошибка не устранена, такой результат существует только в памяти процесса.

## Результат и экспорт

Текущая панель результата показывает контекст опыта, итог, семь строк показателей, статусы и групповые значения. JSON сохраняет полный результат и Ω; CSV содержит табличные значения семи показателей. Неизвестные и интервальные состояния не преобразуются в числовой ноль.

Графики радара, вкладов и Ганта, сравнение серии, анализ чувствительности, повторы, PDF, экспорт PNG и восстановление резервной копии ещё не реализованы. PDF остаётся заблокирован открытым вопросом Q-05 до согласования шаблона. Текущие проверки подтверждают обработку синтетического комплекта; интеграция с реальной выгрузкой ПАК не проверена.

## Хранилище

Схема дополняется таблицей `assessments`; существующие таблицы черновиков и профилей сохраняются. Каждая оценка добавляется отдельной записью. `DraftStore.backup` использует встроенное резервное копирование SQLite, чтобы копия была согласованной при открытом приложении. Импортирование такой копии обратно пока не предоставляется интерфейсом.

# MR: план разработки и база требований этапа 1

**Ветка:** `chore/development-plan` → `chore/route-spec-chapters` (документация основана на ещё не слитой тематической ветке).

**Тип и версия:** документация и исходный файл версии `0.0.0` до реализации; код не меняется. Удалённый MR не создан: инструмент создания MR в окружении недоступен.

## Проблема

`requirements/tasks.md` связывает задачи с главами ТЗ, но не даёт последовательности небольших поставок, проверяемых контрольных точек и порядка закрытия зависимостей для реализации программы. Для старта разработки также нужна исходная матрица требований, реестр решений и план проверок.

## Итог

- Добавлен `docs/development/development-plan.md`: шесть этапов согласно § 11.2 ТЗ, поставки внутри этапов, ожидаемый результат и источники.
- Указаны порядок работы над каждой поставкой, открытые решения и состояние этапа 1.
- Составлена матрица 83 требований и 25 приёмочных сценариев; статус каждого — `не проверено`, доказательств реализации пока нет.
- Добавлены реестр открытых решений, проект логического контракта входа/запуска/диагностики и сценарии AT-01–AT-25.
- Рабочие ε_abs и ε_rel заданы по единицам с разрешения пользователя 24.10.2026; значения ещё предстоит согласовать для приёмки.
- Создан корневой `VERSION` со значением `0.0.0` по правилам проекта.
- В README и `understanding.md` добавлены ссылки и зафиксировано решение пользователя.

## Связанные требования и проверка

План опирается на ТЗ-ОАМ-01 версии 1.0, § 1–11 и приложения А–Г; задачи `requirements/tasks.md`; ADR-0001. Сверены формулировки шести этапов и открытых решений § 11.2–11.3 с исходным DOCX. Из DOCX извлечены 83 уникальных ID требований и 25 ID AT; их число и отсутствие дубликатов проверены. Проверены локальные ссылки и `git diff --check`. Программные и численные тесты не запускались: код не менялся и пока отсутствует.

## Ограничения

Численные допуски пока только рабочие, а не приёмочные. Шаблон PDF, параметры целевой Windows и нагрузки, реальная выгрузка ПАК и календарные сроки ещё не определены. План не объявляет выполнение требований или успешную приёмку.

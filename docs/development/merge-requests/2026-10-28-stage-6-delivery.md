# Этап 6: подготовка Windows-поставки для тестирования

## Исправление Qt platform plugin после пользовательского запуска

Пользователь сообщил, что `opd-gui.exe` на Windows не запускается из-за отсутствия инициализации Qt platform plugin. Проверка старого PE-архива показала отсутствие `qwindows.dll` и `qoffscreen.dll` при наличии основных Qt DLL. Спецификация PyInstaller теперь явно включает оба плагина в путь `PySide6/plugins/platforms`, который использует runtime hook PyInstaller. `scripts/verify_windows_bundle.py` проверяет их наличие в готовом `.exe`; `build_windows.ps1` прерывает сборку при отсутствии. Новый PE-пакет проверен под Wine в чистом профиле с платформой Windows без установленной PySide6. Итог на пользовательской Windows ещё не подтверждён. Изменение остаётся в открытой минорной поставке версии `0.5.1`; статусы DEL-01 и AT-25 не повышаются, оценка **50/84 (59,52%)**, изменение **0,00 процентного пункта**. Прежний локальный ZIP признан неисправным.

## Проблема и результат

Для пользовательской проверки нужен воспроизводимый способ собрать CLI и GUI в Windows `.exe`. В ветке `feat/stage-6-delivery` добавлены PyInstaller-спецификации, PowerShell-сборка и smoke-проверка на контрольном комплекте. Текущая версия кода остаётся `0.5.0`; это старт поставки, а не финальная приёмка.

## Как проверить на Windows

1. Открыть PowerShell в корне репозитория на официальном CPython 3.12 x64.
2. Запустить `Set-ExecutionPolicy -Scope Process Bypass`.
3. Запустить `.\scripts\build_windows.ps1`.
4. Запустить `.\scripts\smoke_windows.ps1`.
5. Открыть `.\dist\opd-gui.exe` и пройти импорт, загрузку Ω, расчёт и открытие результата.

Подробности: [windows-stage6-testing.md](../../development/windows-stage6-testing.md).

# Тестирование поставки этапа 6 на Windows

Эта инструкция собирает локальные исполняемые файлы для проверки приложения. Она не заменяет приёмку: целевые Windows 10/11, архитектура, способ установки, допустимые объёмы и время остаются открытыми в Q-06/Q-07.

## Скачать проверочную сборку

Workflow `.github/workflows/windows-test-build.yml` запускается при push в `feat/stage-6-delivery` на Windows Server 2022 x64 с CPython 3.12. После успешных тестов, сборки и smoke-проверки откройте в GitHub [Actions → Windows test build](https://github.com/mnim1337/OPD/actions/workflows/windows-test-build.yml) → последний успешный запуск ветки и скачайте артефакт `opd-windows-test-<номер запуска>`. Для приватного репозитория требуется вход в GitHub с доступом к проекту. Артефакт хранится 14 дней. Распакуйте его целиком: `dist\opd-gui.exe` — приложение, `dist\opd.exe` — CLI, `configs\examples\profile_demo.json` — профиль для синтетического контрольного опыта, `requirements\PAK_export_reference_4files_v1.zip` — входной комплект. `dist\BUILD-INFO.txt` содержит commit, версию и SHA-256 обоих `.exe`.

Эта сборка предназначена для проверки, а не для финальной приёмки Windows 10/11. Запуск GUI и его полный интерфейсный цикл на пользовательском компьютере следует проверить по маршруту ниже. Если workflow не завершился успешно, его `.exe` не публикуются как артефакт.

## Требования

- Windows 10 или Windows 11 x64;
- официальный CPython 3.12 x64 с доступной командой `py`;
- PowerShell 5.1 или новее;
- клон репозитория на ветке `feat/stage-6-delivery`.

MSYS2 Python для этой сборки не используется: PyInstaller устанавливается из PyPI для обычного CPython.

Если команда `py` не установлена, скрипт автоматически использует команду `python`. Можно также указать её явно: `.\scripts\build_windows.ps1 -Python python`.

## Сборка

Из корня репозитория в PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build_windows.ps1
```

Скрипт создаёт `.venv-stage6`, устанавливает текущий checkout и PyInstaller 6.11.1, запускает тесты и собирает `dist\opd.exe` и `dist\opd-gui.exe`.

После сборки скрипт проверяет состав `opd-gui.exe`: внутри должны быть Qt6Core/Gui/Widgets, `platforms/qwindows.dll` для обычного Windows GUI и `platforms/qoffscreen.dll` для автоматического smoke. Если чего-либо нет, сборка завершается ошибкой и пакет нельзя считать готовым. Старый архив `opd-windows-test-0.5.1-wine.zip`, собранный до этой проверки, содержит неисправный GUI и не должен использоваться.

Если нужно только собрать пакет без тестов, используйте `-SkipTests`. Это сокращает проверку и должно быть отражено в протоколе.

## Smoke-проверка

После сборки:

```powershell
.\scripts\smoke_windows.ps1
```

Проверка распаковывает эталонный четырёхфайловый комплект, выполняет `opd check` и `opd calculate`, проверяет создание `assessment.json`, затем на пять секунд запускает GUI в режиме Qt offscreen. Визуальный GUI запускается отдельно:

```powershell
.\dist\opd-gui.exe
```

В GUI нужно проверить импорт комплекта, загрузку `configs\examples\profile_demo.json`, запуск расчёта, открытие результата и закрытие приложения. Для ручного протокола используйте [маршрут Windows-сверки](windows-visual-acceptance.md).

## Ограничения текущей проверки

Локальная сборка на Linux уже проверяет корректность entry points и упаковки, но не является Windows `.exe`. Smoke-проверка покрывает CLI и синтетический комплект. Реальная выгрузка ПАК, согласованные пределы времени/памяти, установка на обеих целевых версиях Windows и финальная визуальная приёмка остаются отдельными проверками.

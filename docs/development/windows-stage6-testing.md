# Тестирование поставки этапа 6 на Windows

Эта инструкция собирает локальные исполняемые файлы для проверки приложения. Она не заменяет приёмку: целевые Windows 10/11, архитектура, способ установки, допустимые объёмы и время остаются открытыми в Q-06/Q-07.

## Требования

- Windows 10 или Windows 11 x64;
- официальный CPython 3.12 x64 с доступной командой `py`;
- PowerShell 5.1 или новее;
- клон репозитория на ветке `feat/stage-6-delivery`.

MSYS2 Python для этой сборки не используется: PyInstaller устанавливается из PyPI для обычного CPython.

Если команда `py` не установлена, скрипт автоматически использует команду `python`. Можно также указать её явно: `.\scripts\build_windows.ps1 -Python python`.

## Сборка

Из корня репозитория в PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\build_windows.ps1
```

Скрипт создаёт `.venv-stage6`, устанавливает текущий checkout и PyInstaller 6.11.1, запускает тесты и собирает `dist\opd.exe` и `dist\opd-gui.exe`.

Если нужно только собрать пакет без тестов, используйте `-SkipTests`. Это сокращает проверку и должно быть отражено в протоколе.

## Smoke-проверка

После сборки:

```powershell
.\scripts\smoke_windows.ps1
```

Проверка распаковывает эталонный четырёхфайловый комплект, выполняет `opd check` и `opd calculate`, затем проверяет создание `assessment.json`. GUI запускается отдельно:

```powershell
.\dist\opd-gui.exe
```

В GUI нужно проверить импорт комплекта, загрузку `configs\examples\profile_demo.json`, запуск расчёта, открытие результата и закрытие приложения. Для ручного протокола используйте [маршрут Windows-сверки](windows-visual-acceptance.md).

## Ограничения текущей проверки

Локальная сборка на Linux уже проверяет корректность entry points и упаковки, но не является Windows `.exe`. Smoke-проверка покрывает CLI и синтетический комплект. Реальная выгрузка ПАК, согласованные пределы времени/памяти, установка на обеих целевых версиях Windows и финальная визуальная приёмка остаются отдельными проверками.

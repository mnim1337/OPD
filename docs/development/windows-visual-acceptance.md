# Визуальная приёмка этапа 4 на Windows

**Статус на 30.10.2026:** подготовлена методика; пользователь подтвердил запуск `.exe` на Windows и сообщил о чёрном фоне на части страниц паспорта. Полная визуальная приёмка на Windows ещё не проведена. Источник состава экранов — ТЗ-ОАМ-01 версии 1.0, приложение В, рисунки В.3–В.47, и [задачи этапа 4](../../requirements/tasks.md). Макеты показывают синтетические примеры; их значения не являются ожидаемыми результатами расчёта.

## Среда и доказательства

1. Записать commit, `VERSION`, Windows 10/11 и сборку ОС, разрешение экрана, масштаб Windows, версию Python/PySide6/Qt и способ запуска. Для сравнимых снимков использовать окно 1280×850 или больше при масштабе 100%; отдельно повторить проверку при штатном масштабе пользователя, если он иной. Отклонение размера или масштаба фиксировать в протоколе, а не скрывать.
2. Запустить GUI из тематической ветки по [инструкции](setup.md). Проверенный пользователем способ для Windows 11/MSYS2 UCRT64: `PYTHONPATH=src /ucrt64/bin/python -m scanner.gui` после установки `mingw-w64-ucrt-x86_64-pyside6`. Это проверка исходного приложения; поставка `.exe` относится к этапу 6.
3. Использовать копию синтетического [четырёхфайлового комплекта](../../requirements/PAK_export_reference_4files_v1.zip) и [демонстрационный профиль](../../configs/examples/profile_demo.json). Сохранить снимки в `outputs/ui-review/windows/<дата>-<commit>/` с именем рисунка, например `B.09-P05.1.png`. В каталоге также сохранить протокол: входной набор/версия, действия, ожидаемое и фактическое, статус, замечание и путь к снимку. `outputs/` исключён из Git; для удалённой приёмки передать архив снимков отдельно.
4. Сравнивать композицию, видимость и порядок полей, заголовки, русские подписи, состояние кнопок, прокрутку, читаемость и переходы с конкретным рисунком. Реальные значения полей должны соответствовать выбранному входу, а не числам макета. Для таблиц и Ганта проверять, что данные не выдуманы и не обрезаны без возможности просмотра.
5. Статус каждого пункта: **принято**, **замечание**, **не проверено** или **неприменимо с причиной**. Скриншот сам по себе не подтверждает переход или сохранение: действия и результат записать в протоколе. После исправления замечания повторить проверку на новом commit.

## Проверка ручного заполнения на Windows

Для актуальной сборки повторить следующие действия на Windows 10/11 и записать в протокол для каждого блока: имя формы, проверенное поле/строку, введённое и сохранённое значение, результат после повторного открытия, снимок и статус. Автоматические проверки Linux Qt offscreen `test_passport_fields_are_editable_and_restore_nulls`, `test_all_csv_record_fields_round_trip_through_detail_cards`, `test_each_profile_scale_and_weight_is_editable` и `test_manual_draft_reopens_and_calculates_without_source_files` служат подготовкой, а не заменой этого прохода.

1. Из П01 пройти П02 → П03 → П04 → «Открыть формы ввода». На П05.1–П05.9 изменить и восстановить поля каждой карточки; для узлов, соединений, потоков, событий и проверок открыть полную карточку первой записи. Проверить, что необязательное поле с исходным `null` после ввода и очистки снова остаётся `null`.
2. На П05.10–П05.12 изменить и восстановить каждое поле карточки пакета, маршрута и канала, включая пустой приём, счётчики и порядок каналов `path_links`. Проверить добавление, копирование полной записи, вставку диапазона и удаление; уникальные ID после копирования исправить до расчёта.
3. На П05.13–П05.14 открыть опоры всех семи шкал, изменить и восстановить по одной опоре и каждому весу. Проверить ID, статус и основание Ω, а также сохранность экспертных векторов, если они заданы.
4. Сохранить черновик, закрыть приложение, удалить или переместить исходную папку, открыть черновик из П07 и проверить все значения. Выполнить проверку данных и К0–К2; сверить семь показателей и итог с импортированным контрольным комплектом. Открыть сохранённую оценку повторно из П07 без перерасчёта; посетить С01 и С02.
5. Отдельно пройти Д01–Д05, П06.5–П06.6 и остальные состояния по таблице выше. Фактические Windows-снимки и результат каждого действия добавить в `outputs/ui-review/windows/<дата>-<commit>/` и протокол. До такого протокола MAN-01 и UI-12 остаются частичными.

Поля `format_name`, `schema_version`, контракт файла и метаданные размера/SHA-256 являются форматом или формируются программой. `logging_gaps` открывается отдельным JSON-диалогом; определения устойчивости/адаптивности и примечание доступны через «Расширенный ввод паспорта». Эти поля не следует заменять произвольными значениями ради визуальной проверки. При любом отличии от формы или потере значения записать конкретный путь поля и шаг воспроизведения.

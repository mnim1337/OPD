# Расчёт и просмотр К0–К2

Расчёт доступен в редакторе `opd-gui` и из командной строки. В разделе «Эксперименты» пункт «Продолжить предыдущий» открывает экран результатов и черновиков: оттуда можно открыть сохранённую оценку либо выбрать черновик для продолжения. Пункт «Просмотреть результаты» ведёт на тот же экран. После сохранённого расчёта закройте панель результата, вернитесь в редактор и нажмите «Добавить следующий эксперимент», чтобы перейти к вводу следующего опыта в активной серии. Каждый вход и результат сохраняются отдельно. В управлении сериями указано, что копия входного набора не является независимым статистическим повтором. В GUI нажмите «Запуск расчёта»: программа проверит вход и Ω, сохранит их версионный снимок, выполнит К0–К2 и запишет результат в локальную историю. Фоновый запуск показывает текущую фазу, интерфейс остаётся доступным. Кнопка отмены запрашивает остановку на ближайшей безопасной границе между К0, К1 и К2; текущая фаза сначала завершится. Частичный результат не сохраняется, снимок входа остаётся в истории. «История результатов» открывает ранее сохранённую оценку без пересчёта. JSON содержит полный результат вместе с использованным профилем; CSV — семь строк показателей и статусы/границы; радар, полосы вкладов и диаграмму Ганта можно сохранить в PNG. Кнопка «Резервная копия» создаёт согласованную копию SQLite-хранилища, а «Восстановить копию» заменяет локальную историю после проверки выбранной копии.

Если запись результата завершилась ошибкой, GUI сообщает «Расчёт выполнен, результат не сохранён» и позволяет повторить запись без повторного расчёта. Пока результат не сохранён, оставьте приложение открытым: рассчитанные данные хранятся в памяти процесса.

Из командной строки расчёт запускается после [установки](../development/setup.md):

```bash
opd calculate path/to/four-files --profile path/to/profile.json --output assessment.json
```

Папка должна содержать ровно четыре файла формата `PAK_ROUTING_EXPORT_4F 1.0.0`. Профиль Ω — отдельный JSON с `profile_id`, обоснованием (`note_ru` или `basis_ru`) и семью шкалами в `metrics`; демонстрационный профиль находится в предоставленном архиве пяти опытов. Для экспертных весов можно добавить массив `experts`, где каждый элемент содержит `scores` с семью положительными значениями по ключам `P_zad`, `P_pr`, `P_pot`, `P_bal`, `P_ust`, `P_ad`, `P_res`. Профиль с расчётными экспертными весами проверяется до вычисления результата.

При отсутствии `--output` JSON выводится в терминал. В результате для каждого из семи показателей находятся исходное значение с единицей и статусом, нормализованная оценка, частный балл, вес, вклад и трасса. Далее идут четыре группы и итог из 100 баллов. Вещественные числа записаны десятичными строками, чтобы не терять точность при сериализации; отсутствующие и неограниченные границы записаны как JSON `null` с отдельными признаками границ.

Статусы: `exact` — точное значение в условиях модели; `interval` — нижняя/верхняя границы, возможно без конечной верхней; `unknown` — существующий показатель не установлен; `not_applicable` — определение в этих условиях не применяется. При неприменимом показателе полный балл тоже неприменим. Нулевой показатель записан числом `0` и отличается от остальных состояний.

Результат содержит таблицу семи показателей, четыре групповые оценки, общий итог, контекст входа и профиля, графики и трассу расчёта. Неизвестные значения и открытые интервалы остаются видны как таковые, а не подменяются нулём или серединой интервала. Сохранённые оценки можно объединять в именованные серии, добавлять новые расчёты и закрывать серию. При сравнении программа сверяет сеть, заданный трафик, расписание внешних вмешательств, измерительную конфигурацию, шкалы и веса; фактический исход вмешательства не считается заданным условием; при различиях показывает причины и не формирует общий рейтинг.

Анализ чувствительности и статистические повторы относятся к этапу 5. PDF будет реализован после согласования шаблона отчёта (Q-05). Ручная проверка всего интерфейсного цикла и испытание реальной выгрузки ПАК пока не проведены. Сейчас полный точный расчёт поддерживает общие точные модельные часы, точную историю изменений маршрутов и однопутевой режим. При ненулевой или несогласованной временной погрешности временные показатели не выдаются как точные; основание описано в [ADR-0002](../decisions/0002-time-uncertainty-in-core.md). Демонстрационный профиль и пять синтетических опытов не устанавливают норматив эффективности реальной сети.

# Предварительный базовый замер К0–К2

**Гипотеза:** предоставленные пять синтетических комплектов можно последовательно импортировать и рассчитать, получив воспроизводимую запись времени каждой фазы и пика Python-выделений. Этот опыт не оценивает предельную нагрузку и не задаёт норматив времени/памяти.

**Методика:** [скрипт](../../benchmarks/performance/measure_synthetic.py) читает пять отдельных комплектов из неизменяемого архива, использует демонстрационный Ω, в одном процессе выполняет `read_folder` и `calculate`, измеряет wall time через `perf_counter_ns` и пиковые выделения Python через `tracemalloc`. Скрипт записывает один запуск в `benchmarks/statistics/runs.jsonl`, полные данные — в `outputs/runs/<run-id>/`. Случайных процедур нет. Точность показателей здесь не измеряется; отдельные численные тесты используют контрольные ориентиры.

**Параметры:** архив `requirements/эксперимент 5 штук/PAK_5_experiments_with_validation.zip`, профиль `configs/examples/profile_demo.json`, пять случаев. Размеры и число строк фиксируются из самих входов. Допустимые пределы времени, памяти и объёмов не заданы (Q-07).

**Команда:** из корня репозитория после установки зависимостей, с уникальным `run-id`:

```bash
PYTHONPATH=src .venv/bin/python benchmarks/performance/measure_synthetic.py \
  --archive 'requirements/эксперимент 5 штук/PAK_5_experiments_with_validation.zip' \
  --profile configs/examples/profile_demo.json \
  --run-id <уникальный-id>
```

**Критерий функциональной результативности:** пять импортов и пять расчётов без ошибки. Критерий производительности до согласования Q-07 отсутствует. Выводы по фактическому запуску добавляются после измерения с указанием `run-id` и ограничений.
